# Дом дела

Семейное веб-приложение для домашних задач: видно, кто что делает, что запланировано и что уже выполнено. В центре главной страницы — семейный дом, сад которого меняется вместе с выполненными делами.

## Стек и структура

Frontend: React, TypeScript, Vite, React Router, CSS. `src/stranitsy` — страницы, `src/komponenty` — общие компоненты, `src/api` — операции и демо-хранилище, `src/dannye` — стартовые данные, `src/dom` — визуальный дом, `src/stili` — стили. Backend: PHP 8.1+ и MySQL/MariaDB в `backend/`; схема — `backend/schema.sql`. `public/` содержит PWA manifest, иконку и базовый service worker.

## Локальный запуск

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173/dom-dela/`. Для проверок: `npm run typecheck`, `npm run lint`, `npm run build`, `npm run preview`. Если используете pnpm, подходят `pnpm install` и `pnpm run dev`.

## Демо-режим

На экране входа выберите одного из четырёх участников семьи Соколовых. Задачи, сообщения, события, баллы, семейное состояние и настройки сохраняются в `localStorage` данного браузера. Можно зарегистрировать отдельный локальный аккаунт, создать семью или присоединиться к существующей по коду. Взрослому для вступления нужно подтверждение другого взрослого. Демо-данные не синхронизируются между устройствами и не предназначены для конфиденциальной информации.

## PHP API и база

Создайте базу командой `mysql -u root -p < backend/schema.sql`. Настройте переменные `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`, затем запустите `php -S localhost:8000 -t backend/public backend/public/index.php`. Маршруты JSON API начинаются с `/api/`; после входа используйте сессионную cookie и заголовок `X-CSRF-Token`, выданный `/api/login` или `/api/auth/me`. Backend содержит регистрацию, авторизацию, семейные запросы, задачи, резервы, баллы, события, сообщения и уведомления. Публичный сайт GitHub Pages работает в локальном демо-режиме: GitHub Pages не исполняет PHP и не предоставляет MySQL.

## Публикация

Workflow `.github/workflows/pages.yml` собирает frontend при push в `main` и публикует `dist` через GitHub Pages. В настройках репозитория Pages источником должен быть выбран GitHub Actions. Адрес сайта: `https://annacfr.github.io/dom-dela/`.

## Облачная ветка Supabase

Ветка `feature/supabase-cloud` не изменяет публичный сайт до отдельного объединения с `main`. PHP/MySQL остаётся в `backend/` как прежний вариант API; React в облачном режиме использует Supabase напрямую. Локальное демо и его `localStorage` не удаляются и автоматически в облако не импортируются: идентификаторы пользователей у двух режимов различны.

1. В Supabase Dashboard откройте **SQL Editor** → **New query**. Перед запуском убедитесь, что выбран нужный проект, и сделайте резервную копию, если в нём уже есть данные. Миграции создают новые таблицы, функции и политики; не запускайте их повторно после частичного выполнения без анализа ошибки.
2. По очереди вставьте полное содержимое `supabase/migrations/202610210001_osnova.sql`, нажмите **Run** и дождитесь успеха; затем так же `202610210002_chtenie.sql`; последним `202610210003_deystviya.sql`. Не запускайте все три параллельно. Если любой файл выдаст ошибку, остановитесь и сохраните текст ошибки; последующие файлы не выполняйте.
3. В **Authentication → URL Configuration** задайте адрес сайта `https://annacfr.github.io/dom-dela/` и разрешённый redirect `https://annacfr.github.io/dom-dela/`. Для локальной разработки добавьте также `http://localhost:5173/dom-dela/`. Не добавляйте `#/vhod` в redirect: Supabase обрабатывает токен подтверждения в URL до маршрутизации приложения. При включённом подтверждении email нужно открыть письмо перед первым входом.
4. Для локального запуска скопируйте `.env.example` в `.env.local`, укажите `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` из проекта. `.env.local` игнорируется Git. Выполните `npm install`, `npm run test:db`, `npm run dev`. В PowerShell Windows используйте `npm.cmd` вместо `npm`, если выполнение `npm.ps1` запрещено.
5. Для будущей публикации облачной версии добавьте в GitHub **Settings → Secrets and variables → Actions → Variables** те же два имени `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Это публичный ключ, не `service_role` и не secret key. Только после отдельной проверки и решения объединить ветку с `main` workflow соберёт облачную версию.

Проверка после миграций: зарегистрируйте взрослого и ребёнка с разными email, взрослым создайте семью, ребёнком вступите по коду. В двух независимых сессиях создайте задачу, затем ребёнком зарезервируйте, начните и завершите её. Обновите обе страницы: задача, история и баллы должны совпасть. Отдельно проверьте, что аккаунт из другой семьи не видит эти данные. До этого облачная синхронизация считается непроверенной.
